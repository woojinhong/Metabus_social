# 경쟁 제품 마찰과 안티패턴 제안

## 해석 경계

이 문서는 기존 [경쟁 패턴 연구](competitive-patterns.md)의 한계에서 프로젝트 위험을 도출한다. 공개 자료만으로 특정 경쟁사의 실패나 사용자 피해 빈도를 주장하지 않는다. 아래 마찰은 연구 결과와 프로젝트 가설을 구분한 D-024 검토 항목이다.

## 단계별 마찰 지도

| 단계 | 기존 연구가 보여 준 범주 | 프로젝트에서 예상하는 마찰 | 채택할 완화 제안 |
| --- | --- | --- | --- |
| 안내·예약 | 일정형 이벤트, 프로필형 탐색 | 90분 부담, 충원 불확실성, 취소 불안 | 시간 구성, T-24h 확인, 미충원 취소·무벌 재예약을 선명하게 설명 |
| 준비·자격 | 한국형 본인확인과 거래 메시지 범주 | PASS/MVNO/외국인 접근 실패, 개인정보 불안 | 자격 결과와 계정을 분리해 설명하고 문서 수동 우회 없이 재시도·지원 제공 |
| 대기 | 음성방의 역할·연결 상태 | 여섯 명 미도착을 개인 탓으로 추정 | 개인 출석을 공개하지 않고 운영 상태·다음 결정 시각만 표시 |
| 게임 | 프롬프트·사적 입력·차례 | 재치·속도 압박, 지배적 발화, 민감한 질문 | 한 화면 지시, 예시, 패스, 텍스트, 반복, 생각 시간, 점수 없음 |
| 자유 대화 | 공유 활동 후 대화 | 침묵 낙인, 말 많은 사람 공개 제지 | 안전한 이전 주제, 중립 차례 지원, 사적 운영 개입 |
| 관심 선택 | 상호 매칭과 프로필 선택 | 인기 경쟁, 선택 수 추론, 제출 실수 | 0–2명, 비공개, 마감 전 편집, 없음 정상, 제출 결과만 확인 |
| 제한 공개 | 지연 공개와 동의 | 사진을 보상으로 오해, 어깨너머 노출, 거절 압박 | 리소스·청중·목적·만료·캡처 한계를 확인하고 독립 동의 |
| 최종 결과 | 상호성 기반 연결 | 거절 이유 추정, 없음의 실패 낙인 | 내 다음 권한만 표시하고 모두에게 존중하는 공통 종료 경로 제공 |
| 안전 | 신고·차단 표면 | 공개 대면, 긴 서술, 보복 두려움 | 짧은 맥락 선택, 즉시 차단/나가기, 사후 보완, 신고자 보호 문구 |
| 기술 복구 | 음성방 재연결 상태 | 사용자 탓, 중복 제출, 만료 권한 복원 | 현재 상태 재동기화, 권한 보수화, 안전 종료·재예약 경로 |

## 거부할 안티패턴

| 안티패턴 | 위험 | 대체 제안 |
| --- | --- | --- |
| 스와이프·무한 탐색 | 외모·속도·희소성 중심, MVP 범위 이탈 | 예약된 단일 코호트와 단계별 정보 |
| 공개 인기·정답·승자 | 동료 평가와 수치심, 선택 추론 | 개인 완료 확인과 점수 없는 공동 진행 |
| 자동 공개 | 관심을 동의로 오인 | 리소스별 주체 동의와 거절 이유 비공개 |
| 강제 카메라·사진 보상 | 외모 압박과 권리 오해 | 음성 우선, 제한 공개는 선택·만료·청중 명시 |
| 재사용 초대·방 링크 | 전송·재생 공격과 무단 입장 | 계정·예약·기기 결합 일회성 입장 |
| 긴 신고 양식 | 위기 중 포기와 법률 용어 부담 | 즉시 안전 행동 후 최소 맥락, 선택적 후속 자료 |
| 오류를 결석·거절로 표현 | 기술 문제를 사회적 의미로 오해 | 기술 상태와 상대 선택을 분리한 중립 문구 |
| 연락처 교환 유도 | 외부 접촉과 안전 범위 이탈 | 최종 상호 시 10분 음성만 허용 |

## 비판적 검토 질문

- 구조화가 안내를 돕는 대신 지나친 통제나 면접 느낌을 만들지 않는가?
- 비공개를 강조하면서도 현재 청중과 캡처 한계를 충분히 설명하는가?
- 패스·텍스트가 존재하지만 사회적으로 눈에 띄어 낙인이 되지 않는가?
- 재연결 화면이 권한 복구를 약속하거나 상대 선택을 추론하게 하지 않는가?
- 차단과 신고가 조용히 작동하며 결과 상세를 과도하게 약속하지 않는가?

## 사용성 검증 우선순위

1. 제한 공개가 보상·의무가 아니라 독립 동의로 이해되는지 확인한다.
2. 없음·거절·노매치가 타인의 선택을 추론시키지 않는지 확인한다.
3. 음성 패스·텍스트·반복이 눈에 띄지 않고 실제로 사용할 수 있는지 확인한다.
4. 여섯 명 미충원, 참여자 이탈, 재연결을 개인 비난 없이 이해하는지 확인한다.
5. 위험 상황에서 10초 안에 나가기·차단·신고 경로를 찾는지 확인한다.

## 승인 경계

완화안은 [종단 흐름](../../spec/ux/end-to-end-workflow.md)과 [안전한 종료](../../spec/ux/no-match-and-safe-closing.md)에 반영된 제안일 뿐이다. 경쟁사와의 차별화 주장, 시장 성과, 법적 적합성 또는 D-024 승인을 의미하지 않는다.
