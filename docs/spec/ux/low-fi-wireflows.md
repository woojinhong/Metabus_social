# 저충실도 와이어플로

## 사용 경계

아래 구조는 정보 순서와 분기를 검토하기 위한 텍스트 와이어플로다. 최종 레이아웃, 시각 디자인, 라우트, API, 데이터 또는 이벤트 계약이 아니다. 화면 키는 [화면 상태 모델](screen-state-model.md)의 로컬 표기를 따른다.

## 1. 준비와 예약

~~~text
[P01 안내]
  세션 범위 / 공개 단계 / 안전·접근성
        |
        v
[P02 계정] -> 복구/지원 -> 안전 종료
        |
        v
[P03 성인 자격] --실패/장애--> 재시도·지원 / 예약 차단
        |
        v
[P04 사적 프로필] -> [P05 사진·단서 검토]
        |
        v
[P06 세션 선택] -> [P07 확인 대기]
                       |       |
                    확정     미충원/취소
                       |       v
                       |    무벌 재예약
                       v
                  [P08 기기 점검]
~~~

## 2. 입장과 라이브 세션

`P10`은 아래 단계 사이에서 사라지는 독립 규칙 화면이 아니라 영속 라이브
세션 셸이다. 규칙/소개가 첫 콘텐츠 단계로 표시된 뒤 `P11`–`P18`의 현재
단계 콘텐츠 또는 보호된 하위 흐름을 같은 셸의 맥락에서 연결한다.

~~~text
[P08 기기 성공]
        |
        v
[P09 대기실: 규칙·공개 범위·준비]
   | 여섯 명/자격 통과       | 조건 미충족
   v                        v
[P10 영속 라이브 셸]      취소·재예약
   | 첫 콘텐츠: 규칙·소개
   v
[P11 게임1] -> [P11 게임2] -> [P11 게임3]
   | 패스/텍스트/반복/신고가 각 단계에 존재
   v
[P12 자유 대화]
   |
   v
[P13 초기 관심과 이후 보호 흐름]
~~~

`P10`은 현재 단계, 청중/공개 범위, 남은 시간, 연결 상태, 마이크 상태,
참가자 음성 상태, 현재 주 과업과 나가기·안전 접근을 유지한다. 정확한
배치와 제어 방식은 UX-OQ-004 이후의 결정이며 여기서 확정하지 않는다.

## 3. 사적 관심과 공개

~~~text
[P13 0~2명 또는 없음]
   | 명시 제출/미제출 마감
   v
상호 초기 관심이 있는가?
   | 없음                     | 있음
   v                          v
일반 공개 없음 안내       [P14 공개 동의]
                              | 거절/만료
                              v
                         공개 없음 경로
                              |
                    동의 -----+
                      |
                      v
                 [P15 제한 공개]
                      |
          +-----------+-----------+
          |                       |
       닫기/철회              실패/만료/차단
          |                       |
          +-----------+-----------+
                      v
                 [P16 최종 선택]
~~~

동의 화면은 정확한 리소스, 명명된 청중, 목적, 만료, 철회 한계와 캡처 가능성을 행동보다 먼저 표시한다.
승인된 경계는 `P13` 초기 관심, `P14` 동의, `P15` 보기, `P16`
최종 선택과 `P17` 결과를 서로 다른 보호 검토 단계로 유지한다. 이는
각 단계를 독립 route나 component로 확정한다는 뜻이 아니다.

## 4. 결과와 안전한 종료

~~~text
[P16 0~1명 또는 없음]
        |
        v
[P17 내 결과만 표시]
   | 상호 최종 + 권한 유효       | 그 외 모든 정상 결과
   v                             v
[P18 10분 음성]              공통 종료 메시지
   |                             |
   +-------------+---------------+
                 v
          [P19 종료·피드백]
             |         |
           홈/다음     [P20 신고·차단·지원]
~~~

노매치 화면은 타인의 선택, 수, 거절 이유 또는 타임아웃 원인을 노출하지 않는다. 쌍 음성도 연락처·텍스트·카메라를 열지 않는다.
`P19`는 공통 종료이고 `P20`과 합치지 않는다. `P20`은 핵심 흐름의 문맥
안전 진입과 세션 후 지원·사례 목적지를 함께 나타내며 하나의 페이지를
뜻하지 않는다.

## 5. 안전 행동

~~~text
어느 핵심 화면
   |
   +--> [안전 메뉴]
          | 즉시 위험        | 접촉 중단       | 기록 필요
          v                  v                 v
       나가기            차단 반영          최소 신고
          |                  |                 |
          +------------------+-----------------+
                             v
                  접수 확인 / 긴급 도움 분리
                             |
                             v
                       세션 후 보완·상태
~~~

차단·나가기는 신고를 요구하지 않는다. 신고는 긴 법률 분류나 대면 설명을 요구하지 않는다.

## 6. 재연결과 실패

~~~text
연결 저하/백그라운드/새로고침
        |
        v
[현재 화면 위 제한 상태: 다시 연결 중]
        |
   최신 권한·단계 재확인
      /                성공               실패/만료
    |                   |
현재 단계 복귀       재시도·지원·안전 종료
만료 행동은 비활성   취소 시 재예약
~~~

브라우저 뒤로가기·앞으로가기·새로고침·기록 이동은 그 자체로 제출,
철회, 공개 동의 취소 또는 세션 나가기로 처리하지 않는다. 현재 단계와
권한을 다시 확인하며 만료 권한과 미제출 행동을 복원하지 않는다.

짧은 재연결·제출 확인·운영 일시정지는 현재 맥락의 overlay/panel이고,
계속할 권한이 없는 취소·만료·미지원은 blocking screen이다. modal
overlay 안에는 나가기·지원·신고를 포함하고 복귀 후 마이크는 명시적으로
다시 켠다.

## 저충실도 검토 질문

- 사용자가 5초 안에 현재 청중과 가능한 행동을 설명할 수 있는가?
- 패스·텍스트·반복과 나가기·신고가 스크롤이나 더보기 뒤에 숨지 않는가?
- 공개 없음과 노매치가 특정 상대의 선택을 추론하게 하지 않는가?
- 재연결 중 제출·동의·공개 권한을 낙관적으로 복원하지 않는가?
- 200% 확대, 키보드, 스크린리더, 세로형 모바일에서도 순서가 유지되는가?

## React Mock Prototype 전달
