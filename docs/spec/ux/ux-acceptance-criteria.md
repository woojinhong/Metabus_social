# MVP UX 수용 기준

## 사용 규칙

아래 기준은 승인된 UX와 프로토타입 증거를 검토한다. 구현 티켓, 생산
테스트 계약, API, 데이터, 실시간 계약 또는 자동 승인 규칙이 아니다.
각 ID는 이 문서에서만 선언한다.

## 범위·준비

| ID | 수용 제안 | 최소 증거 |
| --- | --- | --- |
| UX-ACC-001 | 참가자가 안내 후 여섯 명, 90분, 음성 우선, 세 게임, 공개 단계, 카메라/결제/연락처 교환 제외를 설명한다 | 진행자 도움 없는 회상 과업 |
| UX-ACC-002 | 계정 인증과 NICE 성인 자격을 별개로 이해하고 저장하지 않는 신원 정보와 실패 시 지원을 설명한다 | 자격 시나리오 인터뷰 |
| UX-ACC-003 | 사진 수집이 세션 공개 동의가 아니며 자동 공개되지 않음을 설명한다 | 미디어 제출 전후 회상 |
| UX-ACC-004 | 예약 확인·미충원 취소·무벌 재예약과 개인 결원 사유 비공개를 이해한다 | 예약 분기 과업 |
| UX-ACC-005 | 마이크 권한, 입력, Bluetooth, 네트워크 문제에서 가능한 재시험·지원·종료를 찾는다 | 실기기 또는 동등 시뮬레이션 |

## 라이브 세션·게임

| ID | 수용 제안 | 최소 증거 |
| --- | --- | --- |

| UX-ACC-007 | 세 게임 모두 같은 위치와 용어로 패스, 반복, 생각 시간, 텍스트 대안, 신고를 찾는다 | 세 게임 순차 과업 |

## 관심·공개·결과

| ID | 수용 제안 | 최소 증거 |
| --- | --- | --- |
| UX-ACC-010 | 초기 관심 0–2명, 없음, 제출 전 편집, 제출 뒤 전체 철회만 가능함과 완전한 비공개를 이해한다 | 선택/편집/없음 과업 |
| UX-ACC-011 | 상호 초기 관심과 사진·정확 나이·직업 범주 공개 동의가 별개임을 설명한다 | 동의 전 회상 |
| UX-ACC-012 | 공개 전에 정확한 리소스, 명명된 청중, 목적, 만료, 철회 한계, 캡처 가능성을 확인한다 | 동의/거절 과업 |
| UX-ACC-013 | 공개 거절·만료·대상 없음이 이유나 상대 선택을 노출하지 않는 정상 경로임을 이해한다 | 공개 없음 시나리오 |
| UX-ACC-014 | 최종 0–1명 또는 없음, 결과 비공개, 상호 시 10분 음성만 열림을 이해한다 | 최종 선택 과업 |
| UX-ACC-015 | 노매치 화면에서 상대 선택·수·이유를 추론하지 않고 종료·차단·신고를 찾는다 | 노매치 설명 과업 |
| UX-ACC-016 | 쌍 음성에서 카메라·텍스트·연락처 교환이 열리지 않고 나가기·차단·신고가 유지됨을 이해한다 | 쌍 음성 시나리오 |

## 안전·복구

| UX-ACC-020 | 재연결이 최신 상태를 다시 확인하며 만료된 공개·발화·선택 권한과 중복 제출을 복원하지 않음을 이해한다 | 네트워크 전환 과업 |
| UX-ACC-021 | 여섯 명 미달은 시작하지 않고, 시작 후 한 명 이탈은 일시정지 후 조건·전원 동의에 따라 계속 또는 취소됨을 이해한다 | 결원 분기 과업 |
| UX-ACC-022 | 공급자·권한·안전 불확실성에서 실패 폐쇄와 재예약/지원 경로가 보이며 개인 책임을 암시하지 않는다 | 실패 시나리오 |

## 프로토타입 판정

- P0/P1 사용성·안전·접근성 결함은 0이어야 한다.
- 핵심 이해 기준은 대상 사용자와 관련 접근성 사용자에서 도움 없이 재현되어야 한다.
- 자동 접근성 검사만으로 통과를 선언하지 않는다.
- 실기기 성능·복구 수치는 [웹·모바일 경험](../web-mobile-experience.md)의 승인 게이트를 변경 없이 따른다.
- 프로토타입 통과는 D-024 UX를 시연할 뿐 OpenAPI, DB, 실시간 또는
  프로덕션 구현 계획을 승인하지 않는다.

## 승인 상태

정보 구조, 화면, 종단/세션/공개/노매치/실패/안전, 모바일, 접근성,
시각 브리프와 카피는 [결정 로그](../../discovery/decisions.md)에 승인되었다.
실사용자·실기기 증거와 생산 계약은 후속 게이트다.
