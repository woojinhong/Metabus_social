# 실패 및 복구 워크플로 제안

## 원칙

- 오류는 사용자·상대·결석·거절을 추정하지 않고 기술 또는 운영 상태로만 설명한다.
- 재연결은 최신 단계·권한·차단·동의·만료를 다시 확인한 뒤 가능한 행동만 연다.
- 만료된 발화, 공개, 선택, 쌍 음성 권한은 복원하지 않는다.
- 중복 제출을 낙관적으로 성공 처리하지 않고 권위 있는 결과를 확인한다.
- 안전 행동과 지원은 연결 상태와 무관하게 가능한 범위에서 유지한다.

## 복구 상태 표현

상태 이름은 UX 문구 분류이며 프로토콜 enum이 아니다.

| UX 상태 | 의미 | 사용자 제안 행동 | 금지 |
| --- | --- | --- | --- |
| 연결 약함 | 지연·손실이 감지되나 현재 권한은 유지 가능 | 네트워크 확인, 계속 듣기, 음성 일시 중지 | 상대 반응을 실패로 추정 |
| 다시 연결 중 | 최신 단계·권한을 확인 중 | 기다리기, 안전 나가기, 도움 | 선택·동의 자동 재제출 |
| 동기화 완료 | 현재 단계와 가능한 행동 확인됨 | 현재 단계로 돌아가기 | 지난 단계 복원 |
| 권한 만료 | 이전 행동 창이 닫힘 | 결과/현재 단계 확인, 지원 | 재시도로 만료 우회 |
| 복구 실패 | 제한 시간 내 안전한 복귀 불가 | 다시 시도, 지원, 나가기 | 무한 스피너·공백 화면 |

| 세션 취소 | 시작/계속 조건 미충족 | 무벌 재예약, 지원 | 개인 책임·결석 사유 노출 |

## 재연결 상세 순서

1. 화면의 민감 콘텐츠와 제출 제어를 제한하고 마이크 상태를 명시한다.
2. “다시 연결 중”과 경과 안내, 나가기·지원·안전 메뉴를 제공한다.
3. 인증, 계정, 예약, 입장, 제재/차단, 세션 단계, 공개·선택·RTC 권한을 다시 확인한다.
4. 현재 단계와 내 확정된 행동만 재구성한다.
5. 만료·취소·제거이면 이유의 허용 범위와 다음 행동을 안내한다.
6. 연결 품질이 회복되면 스크린리더에 한 번만 의미 있는 완료를 알린다.

## 한국어 핵심 마이크로카피

- 연결 저하: “연결이 불안정해요. 현재 마이크 상태를 확인하고 있어요.”
- 재연결: “현재 단계와 권한을 다시 확인하고 있어요. 이전 선택을 자동으로 다시 보내지 않아요.”
- 만료: “연결하는 동안 이 단계가 끝났어요. 이미 닫힌 선택이나 공개는 다시 열리지 않아요.”
- 운영 일시정지: “세션을 잠시 멈췄어요. 개인 사유는 공개하지 않으며, 계속 여부를 곧 안내할게요.”
- 취소: “이번 세션은 시작/계속 조건을 충족하지 못해 종료됐어요. 불이익 없이 다시 예약할 수 있어요.”
- 마이크: “마이크 입력이 확인되지 않아요. 장치를 바꾸거나 도움말을 열어 주세요.”

## 접근성·모바일 요구

- 오버레이가 키보드 초점을 가두되 나가기·지원·신고를 막지 않는다.
- 상태를 색·진동·음향만으로 알리지 않는다.
- 타이머와 연결 알림을 스크린리더에 과도하게 반복하지 않는다.
- 세로형 작은 화면에서 재연결 안내가 단계·마이크·안전 상태를 가리지 않게 요약한다.
- 데이터 사용과 네트워크 전환은 사용자 동의 없는 카메라·녹음을 요구하지 않는다.

## 검증과 승인 경계

승인된 Web/PWA 기기 지표는 [웹·모바일 경험](../web-mobile-experience.md)에 있다. 이 문서의 오버레이, 대기 시간, 재시도 횟수, 문구와 화면 전환은 사용성·실기기 검증 후 D-024 승인이 필요하며 실시간 이벤트 계약을 정의하지 않는다.
