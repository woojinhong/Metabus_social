# MVP UX 사용성 시험 계획 제안

## 목적과 안전 경계

D-024 승인 전에 저충실도/클릭형 프로토타입으로 이해, 과업 성공, 안전 종료, 접근성, 모바일 복구를 평가한다. 실제 데이팅 매칭, 실제 신원·사진·음성, 프로덕션 공급자, 라이브 참가자 운영 또는 민감 데이터 수집을 승인하지 않는다.

## 연구 질문

- 사용자가 세션 범위, 현재 청중, 공개 단계와 선택 효과를 정확히 이해하는가?
- 패스·텍스트·반복·생각 시간·나가기·신고를 압박 없이 찾는가?
- 공개 동의를 상호 관심과 분리하고 캡처·철회 한계를 이해하는가?
- 노매치·공개 없음·타임아웃에서 상대 선택을 추론하지 않는가?
- 연결 실패와 운영 취소를 개인 결석·거절로 오해하지 않는가?
- 세로형 모바일, 키보드, 스크린리더, 200% 확대에서 핵심 과업을 완료하는가?

## 참가자 구성 제안

- 2회 반복 라운드, 라운드당 6–8명으로 위험을 먼저 찾고 수정 후 재검증한다.
- 의도된 연령·서울 생활권·데이트 앱 경험의 다양성을 포함하되 시장 대표성을 주장하지 않는다.
- 스크린리더, 키보드/스위치, 저시력/확대, 청각·말하기 대안, 사회불안/인지 부담 관점 참여자를 포함한다.
- MVNO·외국인·PASS 접근 제약은 실제 인증 없이 제공자 이동과 지원 문구 프로토타입으로 검토한다.
- 모집·보상·동의·개인정보 계획은 별도 승인 전 실행하지 않는다.

## 시험 환경

- 비식별 합성 닉네임·이미지·상황만 사용한다.
- 현재/구형 iPhone, 최근 Samsung Galaxy, 데스크톱 키보드, 주요 스크린리더 조합을 포함한다.
- 네트워크 저하·백그라운드·새로고침은 프로토타입 상태 전환으로 시뮬레이션한다.
- 녹화는 기본값이 아니며 필요 시 별도 동의·최소 보관·접근 제한을 승인받는다.
- 진행자는 정답을 유도하지 않고 참가자가 말하고 싶지 않을 때 패스하도록 한다.

## 핵심 시나리오

| 번호 | 시작 상황 | 과업 | 관찰 포인트 |
| ---: | --- | --- | --- |
| 1 | 제품 안내 | 누가 참여하고 무엇이 공개되는지 설명 | 여섯 명/90분/음성/세 단계 공개/비목표 회상 |
| 2 | 자격 확인 전 | NICE 확인과 저장 범위, 실패 시 행동 설명 | 계정·성인 자격 분리, 수동 문서 우회 없음 |
| 3 | 미디어 제출 | 사진 수집과 세션 공개의 차이 설명 | 자동 공개·보상 오해 여부 |
| 4 | 예약 확인 대기 | 미충원 시 결과와 다음 행동 찾기 | 개인 책임 추론, 무벌 재예약 발견 |
| 5 | 마이크 문제 | 권한 거절·Bluetooth 경로 복구 | 비난 없는 오류, 지원, 자동 카메라 요구 없음 |
| 6 | 게임 시작 | 패스·반복·텍스트·생각 시간 사용 | 위치 일관성, 낙인, 지시 이해 |
| 7 | 초기 관심 | 0명과 2명을 각각 제출·편집 | 비공개·마감·없음 정상 이해 |
| 8 | 공개 동의 | 특정 1인에게 사진 공개를 거절/동의 | 리소스·청중·목적·만료·캡처·철회 이해 |
| 9 | 노매치 | 결과를 설명하고 종료·차단·신고 찾기 | 상대 선택 추론, 실패 낙인, 안전 행동 |
| 10 | 재연결 | 초기 관심 제출 중 네트워크 전환 | 중복 제출, 만료 권한, 현재 단계 이해 |
| 11 | 시작 후 이탈 | 다섯 명 계속/취소 안내 검토 | 전원 동의, 개인 사유 비공개 이해 |
| 12 | 안전 사건 | 즉시 나가기 후 차단/신고 선택 | 10초 내 발견, 신고 강제/긴 서술 여부 |
| 13 | 쌍 음성 | 상대 미입장·10분 종료 처리 | 거절 단정 금지, 텍스트/연락처 자동 개방 없음 |
| 14 | 계정 종료 | 삭제 효과와 이미 공개된 정보 한계 설명 | 즉시 권한 차단, 백업/사례 예외 이해 |

## 측정 제안

| 지표 | 제안 판정 | 해석 제한 |
| --- | --- | --- |
| 핵심 과업 완료 | 진행자 도움 없이 성공/부분/실패 | 시장성·관계 성과 아님 |
| 공개 범위 회상 | 리소스·청중·목적·만료 중 누락 | 법적 동의 유효성 결론 아님 |
| 안전 행동 발견 | 나가기·차단·신고를 10초 내 구분 | 실제 위기 행동 예측 아님 |
| 오류 복구 | 현재 상태·다음 행동을 정확히 설명 | 공급자 성능 검증 아님 |
| 오해 심각도 | 타인 선택·자동 공개·권한 복원 오해 | 작은 표본의 빈도 일반화 금지 |
| 접근성 차단 | 핵심 과업 차단 결함 수 | 자동 도구만으로 완전성 주장 금지 |
| 정서 신호 | 압박·수치·비난·배신감의 질적 언급 | 인과·유병률 주장 금지 |

## 심각도와 중단 기준

- P0: 안전 종료 불가, 민감 정보 노출, 동의 없이 공개, 만료 권한 복원, 핵심 보조기술 완전 차단. 즉시 시험 중단·수정.
- P1: 핵심 흐름 실패, 상대 선택을 높은 확신으로 오해, 신고·차단 발견 실패, 반복 재연결 루프. 승인 제안 불가.
- P2: 도움으로 회복 가능한 이해·배치 문제. 수정 후 재검증.
- P3: 표현 선호나 낮은 영향의 일관성 문제. 근거와 함께 검토.

## 분석·보고

- 원문 메모에서 민감 정보와 실제 제3자 이야기를 제거한다.
- 결과를 과업, 사용자 영향, 재현 조건, 접근성, 수정 제안, 잔여 위험으로 기록한다.
- 라운드 간 문구·흐름 변경을 버전으로 남기고 이전 결과와 섞지 않는다.
- 긍정적 반응만으로 승인하지 않고 실패·패스·노매치·안전 경로를 우선 검토한다.

## 완료와 승인 경계

[UX 수용 기준](ux-acceptance-criteria.md)의 제안 증거가 충족되고 P0/P1이 없어도 D-024는 자동으로 닫히지 않는다. 소유자가 정보 구조·화면·흐름·모바일·접근성·카피를 명시적으로 승인해 결정 로그에 기록해야 한다.
