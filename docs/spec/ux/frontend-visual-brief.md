# 프론트엔드 시각 브리프 제안

## 목적과 경계

이 문서는 향후 React 기반 저해상도 Mock Prototype을 만들 때 사용할 툴 중립적 시각·레이아웃·상태·반응형·접근성 브리프다. 현재 작업은 프로토타입 코드, 애플리케이션 코드, 최종 시각 디자인, 디자인 토큰, 컴포넌트 라이브러리 또는 구현 계약을 만들지 않는다.

프로토타입의 목적은 정보 우선순위, 화면 전환, 실패 경로, 모바일 조작성과 접근성 가설을 검증하는 것이다. 라우트, API, DTO, 데이터 필드, enum, 실시간 이벤트 또는 페이지 권한을 정의하지 않는다.

## React Mock Prototype 원칙

- 실제 서비스가 아닌 정적·로컬 합성 데이터 기반의 저해상도 흐름으로 제작한다.
- 시각 완성도보다 과업 순서, 상태 차이, 안전 행동과 이해 가능성을 우선한다.
- 특정 디자인 도구의 파일 구조나 전용 기능에 의존하지 않는다.
- 제품 규칙과 제안 UX를 주석으로 구분하고 모든 화면에 D-024 승인 대기 상태를 표시한다.
- 행복 경로만 연결하지 않고 없음, 거절, 만료, 차단, 재연결과 취소를 포함한다.

## 시각 우선순위

| 우선순위 | 항상 먼저 보여 줄 정보 | 금지 |
| ---: | --- | --- |
| 1 | 현재 단계, 청중/공개 범위, 남은 시간, 연결 상태 | 인기·선택 수·신고 상태 암시 |
| 2 | 지금 해야 할 한 가지 과업과 짧은 예시 | 긴 규칙을 주 행동보다 앞세움 |
| 3 | 참가자 음성·차례 상태 | 점수·순위·매력 평가 |
| 4 | 마이크, 패스, 선택·제출 같은 현재 행동 | 만료 권한을 활성 상태로 표시 |
| 5 | 나가기, 차단, 신고, 도움 | 안전 행동을 스크롤 끝에만 배치 |

## 레이아웃 브리프

### 모바일 우선

- 세로형 작은 화면에서 상단 상태, 현재 과업, 응답, 하단 제어 순서를 유지한다.
- 단계·청중·시간과 마이크·나가기·안전 행동이 긴 본문이나 참가자 목록에 밀리지 않게 한다.
- 소프트 키보드가 열려도 제출 효과, 취소, 나가기와 신고를 확인할 수 있어야 한다.
- 안전 영역, 브라우저 UI, 화면 회전과 200% 확대에서도 핵심 정보가 가려지지 않아야 한다.

### 넓은 화면

- 모바일 정보 우선순위를 유지하고 보조 설명이나 참가자 상태만 옆 영역으로 확장한다.
- 넓은 화면에서도 현재 과업과 안전 행동 사이의 시각적 거리를 과도하게 늘리지 않는다.
- hover는 보조 단서일 뿐이며 포커스, 클릭, 터치와 스크린리더 경로를 제공한다.

## 시각 언어 제안

- 색: 차분한 중립 기반이며 상태는 텍스트·아이콘·형태를 함께 사용한다. 실제 팔레트는 미승인이다.
- 글자: 한국어 본문 가독성, 명료한 숫자 타이머, 200% 확대와 리플로우를 우선한다.
- 간격: 한 화면 한 핵심 과업을 유지하고 위험 행동 사이에 충분한 간격을 둔다.
- 형태: 권한·상태 차이를 명확히 하되 장식적 카드 중첩과 게임식 보상을 피한다.
- 모션: 단계 변화를 설명하는 최소 동작만 제안하고 감소 동작 설정에서 제거 가능하게 한다.
- 이미지: 얼굴 공개를 보상·권리·승리로 표현하지 않고 실제 참가자 이미지를 사용하지 않는다.

## 공통 UI 역할

| 역할 | 필요한 변형 | 주석할 경계 |
| --- | --- | --- |
| 단계 헤더 | 기본, 임박, 일시정지, 종료 | 현재 권위 상태를 표시할 뿐 제어하지 않음 |
| 청중 표시 | 그룹, 명명된 1인, 나만, 비공개 | 실제 청중, 목적과 만료를 텍스트로 설명 |
| 연결 상태 | 정상, 약함, 재연결, 실패 | 사회적 결과와 분리 |
| 음성 제어 | 음소거, 발화 가능, 재확인 | 자동 마이크 시작 금지 |
| 참가자 상태 | 듣기, 발화, 음소거, 연결 저하 | 인기·선택·신고 정보 금지 |
| 사적 선택 | 미선택, 선택, 없음, 제출, 만료 | 상대 선택 암시 금지 |
| 동의 요약 | 미결정, 동의, 거절, 철회, 만료 | 리소스·청중·목적·만료·캡처 한계 |
| 안전 메뉴 | 나가기, 차단, 신고, 긴급 도움 | 신고 강제 금지, 신고자 보호 |
| 복구 안내 | 연결 중, 복구, 만료, 취소 | 이전 권한 자동 복원 금지 |

## 필수 상태 범위

| 흐름 | 기본 상태 | 반드시 포함할 비정상·대안 상태 |
| --- | --- | --- |
| 계정·자격 | 로그인, 제공자 이동, 적격 | 중립 오류, 만료, 제공자 장애, 지원, 예약 차단 |
| 프로필·미디어 | 사적 입력, 수집 안내 | 임시 저장, 검사, 보류, 거절, 삭제 |
| 예약·기기 | 슬롯, 확인, 마이크 성공 | 미충원, 취소, 권한 거절, 입력 없음, Bluetooth |
| 대기·라이브 | 준비, 규칙, 게임, 자유 대화 | 결원 대기, 일시정지, 연결 저하, 참가자 이탈 |
| 초기 관심 | 0–2명, 없음, 편집, 제출 | 재시도, 만료, 대상 변경, 어깨너머 보호 |
| 제한 공개 | 대상 없음, 동의, 보기 | 거절, 철회, 만료, 미디어 실패, 차단 |
| 최종·결과 | 0–1명, 없음, 내 결과 | 노매치, 상호, 상대 미입장, 권한 만료 |
| 안전·복구 | 안전 메뉴, 최소 신고, 재연결 | 긴급, 첨부 실패, 운영 중단, 취소·재예약 |

## 반응형 검증

- 현재 iOS Safari와 Android Chrome의 세로형 화면을 기준으로 시작한다.
- 데스크톱·태블릿은 같은 정보와 행동을 유지하되 레이아웃만 확장한다.
- 320 CSS 픽셀 폭 상당, 200% 확대, 소프트 키보드, 가로 전환에서 가림·겹침·가로 스크롤을 확인한다.
- 브라우저 뒤로가기와 새로고침 뒤 현재 단계·청중·권한을 다시 확인하는 상태를 포함한다.
- 앱 전환기와 잠금 화면 미리보기에는 얼굴, 관심, 결과, 안전 사례 세부를 노출하지 않는다.

## 접근성 브리프

- 시각 순서와 DOM/포커스 순서를 상태 → 과업 → 응답 → 제어 → 안전으로 맞춘다.
- 모든 핵심 과업은 키보드와 스크린리더로 완료 가능해야 한다.
- 가시적 초점, 접근 가능한 이름, 상태 텍스트, 비색상 구분을 제공한다.
- 타이머는 매초 알리지 않고 시작, 의미 있는 임박과 종료만 알린다.
- 패스, 반복, 생각 시간과 허용된 텍스트 응답을 기본 흐름에 포함한다.
- 감소 동작에서 자동 전환 효과를 제거해도 정보와 과업 의미가 유지되어야 한다.
- 핵심 터치 표적은 최소 44×44 CSS 픽셀의 조작 영역을 제안한다.

## 프로토타입 시나리오

1. 안내 → 계정 → 자격 → 프로필·미디어 → 예약 → 기기 점검 → 대기.
2. 규칙 → 세 게임 → 자유 대화 → 초기 관심.
3. 공개 대상 없음, 공개 동의·거절·철회·만료 → 최종 선택.
4. 노매치, 상호 최종 선택, 상대 미입장 → 공통 종료.
5. 마이크 거절, 네트워크 전환, 새로고침, 운영 일시정지, 취소·재예약.
6. 어느 핵심 화면에서든 나가기, 차단, 최소 신고와 긴급 도움 구분.

## 합성 데이터와 프라이버시

- 실제 신원, 사진, 음성, 연락처, 관심 선택, 신고 사례 또는 운영 데이터를 사용하지 않는다.
- 합성 닉네임과 추상 이미지 자리표시자로 공개 범위와 어깨너머 위험을 시험한다.
- 브라우저 저장소, 로그, 분석 또는 스크린샷에 민감한 예시 값을 남기지 않는다.
- 프로토타입 상호작용을 실제 동의, 권한, 보안 또는 데이터 계약으로 해석하지 않는다.

## 검토 체크리스트

- 각 화면에 시작 조건, 종료 조건, 로딩, 빈 상태, 오류, 만료와 안전 행동이 있는가?
- 현재 청중과 행동 효과가 주 행동 전에 설명되는가?
- 없음·노매치·기술 오류가 타인의 선택이나 개인 책임을 암시하지 않는가?
- 모바일, 키보드, 스크린리더, 200% 확대에서 같은 과업을 완료하는가?
- 프로토타입이 승인된 제품·안전 규칙을 추가·완화하지 않는가?

## 완료와 승인 경계

이 브리프만으로 React Mock Prototype 제작, 최종 시각 디자인 또는 구현을 시작하지 않는다. 별도의 명시적 제작 범위와 D-024 검토가 필요하며, 프로토타입 성공도 API·DB·실시간·구현 계약을 승인하지 않는다.
