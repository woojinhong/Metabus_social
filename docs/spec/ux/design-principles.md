# UX 설계 원칙 제안

## 목적과 경계

이 원칙은 승인된 [MVP 범위](../mvp-scope.md)를 화면·상호작용 제안으로 번역한다. 제품 범위, 세션 시간, 공개 정책, 안전 정책, ADR, 공급자 또는 기술 기준을 변경하지 않으며 D-024 승인 전 구현 기준이 아니다.

## 원칙

| 원칙 | 사용자 필요 | 제안 규칙 | 검토 증거 |
| --- | --- | --- | --- |
| 현재 범위를 먼저 알림 | 누가 무엇을 볼지 통제하고 싶다 | 행동 전에 리소스·청중·목적·만료·취소 한계를 한 화면에 표시 | 공개 이해 과업 |
| 사적 선택은 사적으로 종료 | 거절·인기 노출을 피하고 싶다 | 선택 수, 상대 선택, 이유, 타임아웃 원인을 공개하지 않음 | 노매치 추론 과업 |
| 한 단계 한 핵심 과업 | 긴장한 상태에서도 다음 행동을 알고 싶다 | 단계·남은 시간·현재 행동을 우선하고 부가 설명은 점진 공개 | 단계 전환 과업 |
| 말하기 능력과 매력을 분리 | 빠르고 자신 있게 말하지 않아도 참여하고 싶다 | 패스·반복·생각 시간·허용된 텍스트를 동등한 행동으로 제공 | 게임 접근성 과업 |
| 실패는 비난 없이 복구 | 네트워크 문제를 결석·거절로 오해하고 싶지 않다 | 기술 상태와 사회적 결과를 분리하고 재시도·지원·안전 종료 제공 | 재연결 과업 |
| 안전 행동은 짧고 조용함 | 상대와 대면하지 않고 멈추고 싶다 | 나가기·차단·신고를 핵심 화면에서 짧은 경로로 제공 | 위기 탐색 과업 |
| 모바일에서 핵심을 고정 | 한 손과 작은 화면에서도 통제하고 싶다 | 단계/청중/시간과 마이크/나가기/신고가 스크롤 뒤로 사라지지 않음 | 실기기 과업 |
| 접근성은 별도 모드가 아님 | 보조기술·불안·청각·언어 차이로 배제되고 싶지 않다 | 기본 흐름에 키보드, 스크린리더, 비색상 상태, 대안을 포함 | 보조기술 과업 |
| 동의 철회 한계를 정직하게 설명 | 공개 후 무엇을 되돌릴 수 있는지 알고 싶다 | 새 접근 차단과 이미 본 정보·로컬 캡처의 비가역성을 함께 설명 | 동의 회상 과업 |
| 정상적인 없음과 종료 | 선택하지 않아도 실패로 취급받고 싶지 않다 | 없음, 노매치, 공개 거절, 세션 종료를 정상 결과로 표현 | 감정 여정 과업 |

## 경쟁 패턴 적용

- 채택 제안: 예약·대기·단계 상태, 짧은 프롬프트, 사적 입력, 상호성, 음성 역할·재연결, 안전 표면.
- 거부 제안: 스와이프 경제, 순위·부스트, 공개 인기, 자동 공개, 카메라 강제, 재사용 링크, 연락처 교환.
- 근거와 한계는 [경쟁 패턴](../../research/ux/competitive-patterns.md)과 [마찰/안티패턴](../../research/ux/competitor-friction-and-antipatterns.md)에만 둔다.

## 판단 순서

1. 승인된 제품·안전 규칙을 위반하는가?
2. 사용자가 현재 청중·효과·취소 한계를 이해하는가?
3. 가장 취약한 상태에서 안전하게 멈추거나 복구할 수 있는가?
4. 모바일·키보드·스크린리더·200% 확대에서 같은 과업이 가능한가?
5. 타인의 선택·민감 정보·기술 상태를 불필요하게 노출하는가?
6. 사용성 시험으로 관찰 가능한 기준인가?

## 마이크로카피 규칙

- 현재 상태 → 영향 → 가능한 행동 → 지원 순서로 쓴다.
- 짧은 존댓말을 쓰고 합격, 탈락, 인기, 운명, 보상, 실패라는 사회적 평가를 피한다.
- 타인의 행동을 추정하지 않는다. “상대가 거절했습니다” 대신 “이번에는 다음 음성 대화가 열리지 않았어요”처럼 내 결과만 설명한다.
- 안전 문구는 신고를 강요하지 않고 즉시 나가기와 긴급 도움을 분리한다.

## 승인 전 확인

이 원칙과 [감정 여정](emotional-journey.md), [수용 기준](ux-acceptance-criteria.md)은 함께 검토한다. 일부 원칙의 프로토타입 성공만으로 D-024, API, 데이터, 실시간 또는 구현 계획이 승인되지 않는다.
