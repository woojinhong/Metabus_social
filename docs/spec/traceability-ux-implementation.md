# UX-to-Implementation Traceability Matrix

## Authority and use

The owner approved a proposal-only Implementation Contract documentation phase
in [Issue #7](https://github.com/woojinhong/Metabus_social/issues/7). This first
artifact maps approved UX review units to candidate responsibilities. It does
not promote a production contract and remains `implementation_ready: false`.

`P01`–`P21` and `O01`–`O07` are UX review units only. They are not route,
component, DTO, database enum, real-time state or authorization names. UX
presentation state is not presumed to equal durable server state.

## Matrix interpretation

- **Durable effect** identifies a candidate owner or audit need, not a table,
  field, enum, key or retention implementation.
- **Ephemeral effect** identifies a local/session projection, not a final
  command, event, payload, timer or state machine.
- **Interaction class** is limited to `API candidate`, `Realtime candidate`,
  `Local-only` and `Vendor candidate`; combinations indicate coordination.
- **Authorization** is a least-privilege proposal derived from approved UX and
  security boundaries. Exact roles, grants and page authorization remain open.
- Retention values repeat approved product limits where available; an
  unresolved value is an explicit contract question, not permission to retain.

## Cross-cutting open contract questions

- What actor and role catalog, assignment model and separation-of-duty rules
  satisfy these candidate authorization boundaries?
- Which actions require idempotency, serialization, version comparison or
  explicit acknowledgement, and what is the authoritative time source?
- Which UX transitions need durable audit, which remain reconstructable
  projections, and which data is never persisted?
- How are reconnect, expiry, revocation, block and cancellation ordered without
  restoring stale intent, protected media or microphone publication?
- What legal review changes the approved retention maxima, evidence access,
  deletion proof, processor deletion and scoped-hold behavior?
- What real-device, assistive-technology, vendor, moderation and operational
  evidence is required before any proposal can be promoted?
