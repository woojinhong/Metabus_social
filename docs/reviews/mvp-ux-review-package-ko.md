# 한국 MVP UX 검토 패키지

## 검토 목적

이 패키지는 승인된 한국 MVP와 기술 기준을 바꾸지 않고 D-024 승인
결과와 저충실도 프로토타입 검증 범위를 요약한다. 상세 승인 기록은
[UX 결정 등록부](../spec/ux/open-ux-decisions.md)와 결정 로그에 있다.

## 그대로 유지한 승인 기준

- 서울 활동권, 25–39세 모집, 참여일 기준 만 19세 이상, 정확히 여섯 명과 목표 3:3 호환 코호트.
- 무료·예약형·비공개·음성 우선 90분 세션, 세 게임, 20분 자유 대화, 5분 복구 예산.
- 초기 관심 0–2명, 독립 동의 기반 제한 공개, 최종 0–1명, 상호 최종 선택 시 10분 음성.
- 공개 프로필 탐색, 결제, 카메라, 녹음, 사전 사적 채팅, 연락처 교환, 인기/관계 점수, 생체·수동 문서 검토 제외.
- 백엔드 단계·권한 권위, Web/PWA 우선, 승인된 ADR-001–010, 공급자·데이터·리전 기준.
- 여섯 명 입장 실패 시 시작하지 않음; 시작 후 이탈은 일시정지와 조건·전원 동의 없이는 취소·재예약.

## UX-OQ-001 소유자 승인 기준

- 상태: 2026-07-27 소유자 승인. D-024는 2026-07-28 충족되었다.
- 준비: `P01`–`P05`는 안내된 선형 흐름으로 연결한다.
- 관리: `P06`–`P07`과 `P21`은 가벼운 예약·계정 대시보드에서 관리한다.
- 입장: `P08`–`P09`는 기기 점검과 대기에서 라이브로 인계한다.
- 라이브: `P10`은 규칙/소개부터 종료까지 유지되는 영속 세션 셸이다.
- 보호 흐름: `P11`–`P18`은 셸과 연결된 단계 콘텐츠 또는 보호된 하위
  흐름이며 일반 대시보드 목적지나 최종 라우트가 아니다.
- 종료: `P19`는 공통 종료, `P20`은 문맥 안전·지원과 사후 접근을 맡는다.
- 브라우저 이동: 그 자체로 제출·철회·동의 취소·나가기를 의미하지 않는다.
- 경계: 화면 병합·분리, page/modal/sheet, 최종 route·화면 권한, 제어
  위치, timer·participant 표현, reconnect, 모바일 고정 영역, 접근성
  세부, component와 API·DTO·데이터·실시간 계약은 승인되지 않았다.

## UX-OQ-002 소유자 승인 기준

- 상태: 2026-07-27 소유자 승인. UX-OQ-001은 유지되고 D-024는 2026-07-28 충족되었다.
- 독립 검토 화면: `P01`–`P09`; 공통 준비 layout 사용 가능.
- 영속 셸: `P10`; `P11`–`P18`은 stage content 또는 protected subflow.
- 보호 경계: `P13`–`P17`은 의도·청중·권한·노출이 달라 각각 유지한다.
- 종료·안전: `P19`는 공통 종료; `P20`은 문맥 안전 진입과 사후 목적지.
- 계정: `P21`은 lightweight dashboard의 개인정보·계정 목적지.
- 운영: `O01`–`O07`은 역할 필터링 콘솔의 분리된 검토 capability이며
  sanction, appeal, audit 역할을 분리한다.
- 상태 표현: inline, overlay/panel, blocking screen, sheet/dialog,
  post-session destination으로 분류하되 실제 UI 단위는 확정하지 않는다.
- 미결: route·권한·component·상태 동작과 UX-OQ-003–013 세부 전체.

## 핵심 한국어 문구 검토

| 상태 | 제안 핵심 문구 | 확인 질문 |
| --- | --- | --- |
| 패스 | “지금은 패스해도 괜찮아요.” | 낮은 관심·불이익으로 오해하지 않는가 |
| 공개 전 | “이 정보는 지금 선택한 한 사람에게만 제한 시간 동안 보여요.” | 리소스·청중·만료가 충분히 구체적인가 |
| 공개 거절 | “공개하지 않아도 괜찮고 이유는 상대에게 전달되지 않아요.” | 강요·보복 우려를 줄이는가 |
| 노매치 | “이번에는 다음 음성 대화가 열리지 않았어요.” | 거절·실패·상대 선택을 추론하지 않는가 |
| 재연결 | “현재 단계와 권한을 다시 확인하고 있어요.” | 이전 선택 자동 재제출로 오해하지 않는가 |
| 취소 | “불이익 없이 다른 시간을 선택할 수 있어요.” | 개인 결원 사유를 암시하지 않는가 |
| 신고 | “먼저 나가거나 차단할 수 있어요. 신고는 필요한 만큼만 알려 주세요.” | 신고를 안전 종료 조건으로 강요하지 않는가 |

## 경쟁 패턴 판단

- 채택 제안: 예약·대기·단계 표시, 짧은 프롬프트, 사적 입력, 상호성, 음성 상태/재연결, 접근 가능한 안전 표면.
- 거부 제안: 스와이프·순위·부스트, 인기·정답 수치, 자동 공개, 카메라 강제, 재사용 링크, 연락처 교환, 얼굴 공개 보상화.
- 근거와 한계: [경쟁 패턴](../research/ux/competitive-patterns.md), [마찰/안티패턴](../research/ux/competitor-friction-and-antipatterns.md).

## 승인 후 잔여 증거 공백

- 대상 한국어 사용자가 공개 동의·캡처 한계·노매치 문구를 실제로 이해한다는 증거가 없다.
- 패스·텍스트·반복·시간 추가가 낙인 없이 작동한다는 참가자 증거가 없다.
- iOS/Android 실기기에서 라이브 셸·백그라운드·Bluetooth·네트워크 복구 검증이 없다.
- 스크린리더·키보드·200% 확대·청각/말하기 대안의 과업 수준 검증이 없다.
- 저충실도 Mock Prototype은 합성 데이터로만 검증하며 실기기·실사용자
  결과, 최종 시각 디자인, 디자인 토큰과 생산 계약을 대체하지 않는다.

## UX 게이트 결과

UX-OQ-001–013은 모두 승인되었고 D-024 UX 게이트는 충족되었다. 이는
격리된 저충실도 React Mock Prototype만 허용한다. 프로덕션 코드와
API·DB·실시간·Vendor·인프라 계약은 새 명시적 단계가 필요하다.
구현 범위와 로컬 검증 증거는 [프로토타입 검증 기록](mvp-ux-prototype-validation-ko.md)에 있다.

## 계속 금지

OpenAPI/AsyncAPI, DTO, DBML, 데이터 열·enum, 마이그레이션, 실시간 이벤트/상태 머신, 페이지 권한, 구현 Issue, 애플리케이션 코드, 디자인 도구 전용 파일, 공급자·ADR 변경 또는 프로비저닝을 만들지 않는다.
